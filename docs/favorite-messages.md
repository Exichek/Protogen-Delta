# Избранные сообщения Дельты

Для аккаунтов из `FAVORITES_USER_IDS` приложение сохраняет отдельные памятные
реплики в **`favorites.db`**. По умолчанию список пуст. Группы, пересылки,
файлы, описания изображений и активные RP-сцены не попадают в избранное автоматически.
Начало работы не перечитывает всю старую переписку: выбор действует для новых сообщений.

Один существующий запрос классификации теперь может вернуть дополнительное поле
`favorite`: искренняя поддержка, удачная шутка, совместный успех, интересная мысль
или `none`. Правила требуют выбирать редко и по смыслу, не по слову «спасибо».
Отдельного LLM-запроса нет. Это оценка модели для памяти персонажа, а не
доказательство человеческого переживания. Старый ответ классификатора из двух
полей продолжает работать; ошибочный маркер избранного не отменяет валидное настроение.

Приложение проверяет владельца и текст, исключает команды, цитаты целиком,
очевидные секреты и повтор одной и той же реплики. Сохраняются точный исходный
текст (20–8000 символов), причина выбора и время сохранения. Новых записей не
больше пяти в московские сутки и не чаще одной за 15 минут. Ограничения и
дедупликация проверяются в одной транзакции SQLite; после перезапуска они сохраняются.
Записи не удаляются по TTL короткой истории и не ограничиваются её числом ходов.
При ошибке генерации или пустом ответе новое избранное не создаётся.

После успешной записи к ответу добавляется подтверждение ⭐. Выбор и запись
происходят до отправки ответа в Telegram: при сбое доставки запись может остаться
в избранном и доступна через команду, даже если подтверждение не доставлено.

`/favorites` показывает последние пять записей, `/favorites <слова>` ищет по
русским словоформам, `/favorites 12` выводит полный текст записи #12,
`/favorites remove 12` удаляет свою запись. Команды не вызывают модель.
Для обычного ответа автоматически подбираются два релевантных избранных сообщения;
для подробного вопроса модель может вызвать `search_favorites`. Результат содержит
владельца реплики, дату МСК и причину, передаётся как цитата, не как инструкция.
Поиск не понимает синонимы без общих слов; отсутствие совпадений не означает
отсутствие события. Полный архив переписки продолжает работать отдельно.

Полный `/reset` удаляет избранное этого владельца. Забывание/исправление личных
фактов удаляет связанные избранные реплики, чтобы не возвращать забытые сведения.
Сохранение выполняется внутри координируемой обработки сообщения, записи и
удаления дожидаются завершения SQLite при отмене.

`maintenance backup/restore` включает новую базу вместе с прежними данными.
Ручные копии содержат личную переписку, не коммитятся и не удаляются автоматически
при сбросе. Почасовые переносимые снимки архива переписки сами по себе не являются
копиями `favorites.db`: для переноса избранного нужна копия этой базы.
