# Чтение исходников и обзор для администратора

`CODE_REVIEW_USER_IDS` задаёт отдельный список Telegram ID через запятую. По умолчанию
он пуст: роль создателя и обычные права администратора этот доступ не выдают.
Команда `/code_review` доступна только этому человеку в личном чате, без пересылки.
Без аргументов команда открывает последний успешный сохранённый отчёт, в том числе
после перезапуска и истечения часового интервала. Для чтения сохранённого отчёта
исходники не сканируются и модель не вызывается. Если отчёта ещё нет, начинается обзор.
`/code_review new` явно запускает новый обзор до трёх изменённых модулей либо
основных модулей ответа, инициативы и запуска. `/code_review services/proactive.py`
и `/code_review new services/proactive.py` явно выбирают конкретный файл.

В том же личном чате модель может искать и читать код инструментами `search_source`
и `read_source`. В группах они недоступны, даже создателю. ID задаётся приложением
через ContextVar и не входит в аргументы модели. Дополнительная проверка стоит в
самих инструментах. Чтение ограничено 120 строками/8000 символами; поиск — 15 совпадениями.

Читается установленный Python-пакет: `core`, `services`, `repositories`, `handlers`,
`main.py` и `config/settings.py`. Это версия кода работающего бота, а не произвольная
папка сервера. Данные, `.env`, Git, архивы, картинки, промпты, тесты и JSON-каталоги
не входят в список. Пути с обходом каталогов и внешние симлинки не читаются.
Дополнительный запрет действует на скрытые файлы, каталоги данных/резервных копий,
`secrets`, `credentials` и модули `secrets.py`, `credentials.py`, `keys.py`, `tokens.py`, `env.py`.
Секретные литералы, вложенные словари и значения аргументов по умолчанию маскируются.
Приложение дополнительно скрывает известные ему значения ключей, токенов и адреса прокси,
даже если они оказались в исходнике под произвольным именем. Инструмент не читает окружение.
Изменения файлов, shell, исполнение Python и развёртывание не предоставлены.
Перед выдачей файлы проходят разбор `ast.parse` работающим интерпретатором;
это не импорт модулей и не проверка поведения. Аудитору передаются точная версия
Python и результат этого этапа. В Python 3.14 список исключений без `as` допускается
без скобок по [PEP 758](https://peps.python.org/pep-0758/). Маскирование секретных строк
может нарушить видимую структуру фрагмента и не доказывает ошибку исходного файла.
Аудитору предлагается дочитывать связанные ветви и условия перед выводом о дефекте,
не заполнять количество замечаний и отличать гипотезу от воспроизведённой ошибки.
Это уменьшает ложные выводы, но не гарантирует правильность каждого отчёта модели.
Можно получить [предложение diff](implementation-facts.md) с проверкой контекста
и отдельной отметкой результата; бот не применяет его и не запускает тесты.
Для аудита запрашивается режим размышлений, если разрешено
[адаптивное включение](adaptive-reasoning.md). Часовой лимит и кэш при этом сохраняются.

Фоновая задача проверяет изменения раз в час и запускает обзор не чаще одного раза
в сутки для каждого разрешённого аккаунта. Первое включение фиксирует исходную
версию без платного обзора и сообщения. На следующих изменениях рассматриваются
до трёх файлов за сутки; оставшиеся изменения сохраняются для следующих проверок.
Результат приходит этому же аккаунту. Без изменений новых запросов и уведомлений нет.
Новый ручной обзор допускается раз в час; открытие сохранённого отчёта не расходует
этот лимит. Короткое автоматическое уведомление обозначено как фрагмент и содержит
команды открытия полного текста и нового обзора. Отчёт сохраняется без среза на
6500 символах; длинный текст выдаётся несколькими Telegram-сообщениями.
Состояние, время попытки и отчёт сохраняются в таблице `code_reviews` базы `memories.db`.
Ошибка модели оставляет последний успешный отчёт и не вызывает частые повторы;
неудавшаяся доставка повторяется со
сохранённым отчётом, без новой генерации. Потеря ответа Telegram перед сохранением
отметки может привести к повторной доставке.

Обзоры входят в настроенные личные и общую суточные квоты API-попыток. Модель видит сначала
фрагменты файлов и может прочитать дополнительные строки; обзор частичный,
тесты не запускаются. Промпт требует пути/строки, условия ошибки и отличия
предположения от доказанного дефекта. Результаты инструментов являются данными;
на уровне исполнителя запрещены вызовы инструментов вне выбранного для запроса набора.
