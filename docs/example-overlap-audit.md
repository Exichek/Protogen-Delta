# Совпадения ответов с каталогом примеров

`scripts/audit_example_overlap.py` разбирает уже сохранённый оценочный отчёт.
Ключи, сеть, Telegram и модель не используются. Это отдельный этап наблюдения:
совпадение помогает найти место для чтения, но не признаётся ошибкой и не
меняет ответы, оценки или рабочие промпты.

```powershell
poetry run python scripts/audit_example_overlap.py --report .tmp/example-model.json --output .tmp/example-overlap.json
```

Поддержаны результаты `evaluate_behavior.py`, парные результаты
`compare_example_contracts.py` и локальная обёртка `report` с отпечатками
измеренных исходников. Для каждого реального ответа проверяется совпадение
версий обоих TXT с записанными в отчёте. При несовпадении разбор прекращается:
для старого отчёта можно передать каталог его образцов через `--examples-dir`.
Проверяются только образцы голоса и сцены, а не версия всего движка.

Из строк с разделителем `→` берётся только ответ, без вопроса-образца.
Сравниваются непрерывные последовательности слов без регистра и пунктуации.
Порог по умолчанию — восемь слов, его можно изменить `--minimum-words`.
Длинное совпадение помечается также, когда эта же последовательность есть
в текущем сообщении пользователя: прямое цитирование может быть уместным.
Семантические перефразирования и причины чувств таким способом не определяются.

Отчёт сохраняет ID сценария, вариант, повтор и ход, прежние `checks` и
`quality_review`, источник и строку образца, число совпавших слов и диапазон
токенов ответа. Текст ответа и сообщения не копируется; исходный файл связан
с результатом через SHA-256. Номера токенов здесь означают слова этого
сравнения, а не токены провайдера. Выход не может перезаписать входной файл.

Предпросмотр всегда остаётся `preview_not_assessed`: заглушки не оцениваются
даже при случайном совпадении текста. Частичный прогон сохраняет признак
незавершённости и исчерпания бюджета. В реальном режиме статус `signals_only`
не заменяет ручную оценку и не делает прежнюю неудачную проверку успешной.
CLI возвращает успех при корректном разборе, даже если совпадения найдены.
Автоматического выбора кандидата или запрета общих фраз нет.

Оба файла образцов входят в проверяемый каталог, но не обязательно в каждый
реальный запрос. Поэтому совпадение не доказывает, что модель скопировала
именно подключённый блок. Отсутствие совпадений также не доказывает
достоверность воспоминаний, разнообразие речи или сохранение характера.
Отчёты предназначены для локальной игнорируемой `.tmp`, а не для публикации.

## Разбор ранее полученных ответов

На прежнем наборе из 48 отдельно разрешённых ответов найдены два совпадения
длиной 12 слов с образцом про шутку на прочность: `isolated`, повтор 1,
и `legacy`, повтор 2, в сценарии `playful_voice`. Оба места ранее замечены
при чтении; теперь сигнал воспроизводим без нового обращения к модели.
Прежние формальные проверки у этих ответов были `passed`, ручная оценка
осталась `pending`. Это показывает ограничение прежних узких шаблонов,
не преимущество одного варианта. Изоляция образцов остаётся выключенной.

Это повторный разбор старого набора, а не замер ответов после последних
исправлений инициативы. Ещё остаются смысловая проверка выдуманных событий,
оценка голоса пользователем и отдельное сравнение настоящих ответов при
новом разрешённом бюджете. Дневная квота обычного чата не выдаётся за
авторизацию оценочных расходов.

## Повторы в одном синтетическом диалоге

`history_matches` отдельно отмечает длинные совпадения с последними восемью
предыдущими ответами того же сценария, варианта и повтора эксперимента.
Результаты разных ветвей не смешиваются. Число таких ответов находится в
`responses_with_history_matches`. Запрошенное повторение может быть уместным;
отметка не запрещает фразу и не заменяет оценку смысла. Для изучения последствий
готовых образцов подготовлен [отдельный кандидат](style-guidance-candidate.md).

Ходы с generation_error не оцениваются и отдельно учитываются в
`generation_skipped`: служебный ответ приложения не считается речью модели.
