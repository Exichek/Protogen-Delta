# Источники сведений об инициативе

После сравнения изоляции примеров в обоих вариантах оставались выдуманные
причины инициативы. В сборке обнаружено прямое противоречие: даже без
подтверждённой отправки подсказка начиналась с утверждения «после инициативы»
и предлагала объяснить, что Дельта хотел сказать. Лишь затем шло предупреждение
об отсутствии подтверждения. Это ошибка передачи сведений приложением.

## Разделение в коде

`InitiativeEvidence` получает не больше двух самостоятельных реплик из четырёх
последних открытых ходов этого чата, не больше 500 знаков каждой. Существующий
признак `ConversationTurn.proactive` выставляется после подтверждённой отправки;
новые записи в память для этого исправления не добавляются.

Для подтверждённой отправки подсказка предлагает продолжить смысл её текста.
Когда отправка не найдена, выбирается другая ветвь: пользователь обращается
сейчас, прежняя инициатива не установлена. Это не доказательство, что бот вообще
ничего не отправлял: краткая история не равна полному журналу. Новое предложение
поболтать остаётся допустимым, вымышленное прошлое действие не подтверждается.

В данных раздельно передаются:

| Поле | Значение |
|---|---|
| `delivery_status` | `confirmed` либо `not_in_context` |
| `messages` | Подтверждённые слова, отдельно от инструкций |
| `past_motive` | `null`: отдельная причина прошлого действия не записана |
| `emotion_scope` | `current_reply_only`: накопленные эмоции задают тон сейчас |

Если в самой доставленной реплике названа тема или желание, можно опереться на
её смысл. Из факта доставки не следуют тишина, ожидание, пробуждение или занятия
между сообщениями. Текущая усталость не становится причиной старого приглашения.

## Приоритет конкретного предмета

Раньше общая подсказка инициативы также могла добавляться поверх подтверждённого
автообзора, сообщения создателя или Telegram-цитаты. В активной RP она могла
навязать требование одного-двух коротких предложений. Теперь она не включается,
когда у текущего ответа есть такой более конкретный предмет либо действует RP.
История при этом не удаляется и остаётся доступной модели.

Для цитаты используется признак из настоящих полей Telegram в исходной части
пачки. Для автообзора и сообщения создателя — результат доверенного сервиса
подтверждённой доставки. Фраза пользователя о «подтверждённой отправке» сама по
себе этот признак не создаёт. Подключённый сервис, не вернувший контекст, также
не отключает обычное продолжение инициативы. Прямой технический вопрос по-прежнему
получает обычную техническую сборку.

## Проверки и границы вывода

Регрессионные тесты проходят через движок, настоящие SQLite-репозитории доставки
и маршрутизацию одиночных сообщений и пачек с подменённой сетью. Проверяются
отсутствие противоречивого утверждения, сохранение авторства и истории, приоритет
цитаты, автообзора, сообщения создателя и активной RP. Существующие проверки
перезапуска, эмоций, закрытых ходов и изоляции пользователей сохранены.

```powershell
poetry run python scripts/evaluate_behavior.py --cases scripts/initiative_evidence_cases.json --output .tmp/evidence-preview.json
```

Шесть сценариев проверяют ветви сборки без API и без оценки ответов заглушки.
Тексты личности, голоса и RP не переписаны. Кандидат изоляции примеров из
предыдущего сравнения остаётся выключенным: основной контракт — legacy.
Шестнадцать контрольных сборок основного промпта сохраняют прежние SHA-256;
динамическая подсказка инициативы намеренно изменена.

Новых платных запросов для этой правки не выполнялось. Прежний прогон из 48
ответов выявил проблему, но не измеряет эффект исправленной сборки. Тесты
подтверждают корректность передаваемых данных и выбора ветви, а не гарантируют
отсутствие выдумок во всех будущих ответах модели.
