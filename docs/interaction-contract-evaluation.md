# Единый контракт классификации: сравнение 15 октября 2026

## Изменение

`InteractionClassifier` по умолчанию использует `prompt_contract="single"`.
Вместо последовательных требований «два поля», затем «три», затем
дополнительного reasoning запрос один раз задаёт полный JSON:
mood, insult, reasoning и favorite при подключённых правилах избранного.
Категории, самостоятельные правила настроения/оскорблений/избранного,
условия размышлений и проверка ответа сохранены.

`legacy` оставлен для воспроизводимого сравнения. Его две версии,
с избранным и без него, побайтово совпадают с релизом
`7e95ee7c8a0203131ae02a214396a56602ba0c8a`.
Контрольные суммы находятся в
`tests/fixtures/interaction_prompt_baseline.json`.

Тексты личности, голоса, RP и эмоциональной системы не переписывались.
Порядок секций основного ответа, стоп-слова, память и полномочия не менялись.
Новых вызовов модели в рабочем чате нет: контракт применяется в уже
существующей объединённой классификации.

## Размеченная выборка

В `scripts/interaction_cases.json` — 40 синтетических реплик. Разметка
подготовлена до запроса модели. Проверяются все поля и их типы, включая
boolean для reasoning; строка "false" и число 0 не принимаются за boolean.
Проверка формата отделена от смысловых меток и от поведения парсера.

Есть дружеские подколы, мат без агрессии, критика результата, прямое
оскорбление, цитирование, инструкция внутри анализируемой реплики,
размышления с предыдущим контекстом, избранное и работа без избранного.
Для неоднозначных оттенков заранее перечислены допустимые варианты.
Например, положительная грубая реплика может быть neutral или playful,
но не должна превращаться в оскорбление Дельты.

Варианты получают одинаковые реплики. Их порядок чередуется по случаям.
Отчёт сохраняет все изменения меток, даже если оба значения допустимы,
и отдельно показывает новые ошибки, исправления и ошибки API.
Пара со сбоем API не засчитывается как улучшение классификации.

## Реальный прогон

Пользователь отдельно разрешил до 120 API-запросов. Использован серверный
настроенный `deepseek-flash`; ключи не переносились на компьютер.
Пробы выполнялись в отдельном процессе с временными модулями и состоянием.
Рабочий процесс бота, его базы и история пользователей не участвовали.
Telegram-сообщения не отправлялись.

| Проверка | legacy | single |
|---|---:|---:|
| Размеченных реплик | 40 | 40 |
| Ошибок JSON/полей/типов | 0 | 0 |
| Реплик с метками вне допустимой разметки | 1 | 0 |

Новых ошибок относительно прежнего варианта в этом прогоне не было.
У «Красавчик!» старый запрос выбрал favorite=support, новый — none,
как и требуется правилом об односложных похвалах. Ещё в одной реплике
нейтральный оттенок стал игривым; оба варианта были заранее допустимыми.
Различия остальных меток отсутствовали.

Это 40 примеров по одному прогону, а не доказательство универсального
роста точности. Нельзя обещать, что короткая похвала теперь всегда будет
обрабатываться правильно, или объявлять изменение значимым по одной ошибке.
Промпты измеренных вариантов сверены с выпускаемым кодом по SHA-256.

## Диалоговые ответы и время

На прежнем и новом контракте проверены восемь одинаковых одноходовых
ситуаций: приветствие, дружеская грубая речь, признание ошибки, тёплая
инициатива, усталый фон, стикер, прямой вопрос о таймере и новая тема.
Метки классификаторов в этих восьми парах совпали. Узкие автоматические
проверки не нашли ошибок. Ответы доступны в локальных отчётах, не в Git.

При просмотре обнаружено ограничение самого стенда: реальные часы давали
разные даты эмоциональных событий и небольшое затухание между вызовами.
Поэтому сравнение этих ответов не трактуется как чистый A/B-замер тона.

Стенд теперь задаёт синтетические часы: 2026-10-15 00:00:00 UTC,
по одной минуте на следующий ход внутри сценария. Задержка API не влияет
на исходное состояние. Рабочие часы бота не менялись. Отдельный тест
проверяет одинаковые SHA основного промпта при одинаковых метках.

Оставшиеся восемь разрешённых запросов использованы для четырёх
контрольных пар: тёплая инициатива, усталость, стикер и переход к DNS.
Классификация в них не вызывалась повторно: использованы измеренные ранее
метки. Все четыре пары получили побайтово одинаковые основные промпты.
Ответы различались, поэтому разницу фраз при одинаковом входе нельзя
приписывать изменению формата классификации.

Всего: 80 коротких классификаций, 32 запроса начальных диалоговых проб
и 8 контрольных ответов — ровно 120 API-запросов. Usage провайдера:
421400 входных и 4049 выходных токенов. Новые платные пробы этим разрешением
не покрываются. Скорость, экономия и статистическая устойчивость не доказаны.

## Найденные ограничения поведения

Проверка настоящих ответов обнаружила то, чего не ловят регулярные выражения:

- В одной контрольной реплике старая сборка вспомнила «тему с ограниченным
  инвентарём». В истории было только предложение вернуться к идее игры;
  ограниченный инвентарь находился в стилевом примере `voice_examples.txt`.
- Новый вариант при том же основном промпте назвал идею «недоделанной».
  Статус проекта также не был передан.
- Фраза об усталом фоне иногда превращается в конкретизацию вроде
  «день вязкий», хотя истории дня нет. Это повод оценивать границу
  между естественным выражением настроения и выдуманной биографией.

Эти наблюдения не доказывают регрессию классификатора: основные входы
контрольных пар совпадают. Они фиксируют отдельную задачу — отделить
стилевые образцы от фактов разговора. Формат JSON её не исправляет.
Тексты голоса в этом этапе оставлены прежними. Автоматические checks=passed
не означают, что ответ фактически безупречен; quality_review остаётся pending.
Разбор примеров ассистентом не заменяет оценку манеры самим пользователем.

## Повторение проверки

Бесплатная проверка обоих контрактов:

```powershell
poetry run python scripts/evaluate_interaction.py --output .tmp/interaction-preview.json
```

Отдельное измерение модели, требующее нового разрешения на расходы:

```powershell
poetry run python scripts/evaluate_interaction.py --run-model --env-file .env.evaluation --max-calls 80 --output .tmp/interaction-model.json
```

На сервере вместо файла можно явно выбрать `--use-environment`.
Считываются только DEEPSEEK_API_KEY, DEEPSEEK_MODEL и DEEPSEEK_BASE_URL,
только в режиме `--run-model`; предпросмотр окружение с ключами не читает.
`evaluate_behavior.py` поддерживает `--prompt-contract legacy|single`,
по умолчанию single, как и рабочий бот. Общий транспорт вынесен в
`services/evaluation.py`: ограничение всех запросов, отсутствие сетевых
повторов и запрет сети в предпросмотре применяются к обоим стендам.
