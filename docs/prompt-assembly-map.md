# Карта сборки промпта

Каждая сборка основного ответа теперь состоит из именованных блоков
`PromptAssembly`. Рабочий движок по-прежнему возвращает одну строку:
порядок, пробелы, заголовки, тексты и условия выбора сохранены.
`PromptComposer.compose()` и `ResponseEngine._build_prompt()` сохраняют
прежние сигнатуры и возвращаемые строки. Кандидат `isolated` остаётся
выключенным по умолчанию. Дообучение и новые запросы к модели не добавлены.

Карта нужна для ревизии правил: раньше общий отпечаток показывал изменение,
но не объяснял, какая часть сборки выросла или подключилась. Теперь можно
увидеть тематические модули, возможности приложения, разговорный стиль,
состояние, память, факты, правила реакции, текущую сцену, подтверждённые
сведения приложения и образцы голоса. Условные секции видны только тогда,
когда они действительно попали в запрос. Пустые секции не занимают места.

## Отчёт стенда

```powershell
poetry run python scripts/evaluate_behavior.py --output .tmp/behavior-preview.json
```

У каждого хода поле `prompt_assemblies` содержит карты собранных основных
промптов. Обычно карта одна; при остановке до генерации список пуст.
Это не карта запросов классификации, истории сообщений или схем инструментов.
Каждый элемент карты содержит только:

- `name` — имя блока из кода;
- `start` и `end` — полуинтервал в символах Python готовой строки;
- `chars` — его длина вместе с принадлежащими блоку разделителями.

Например, `state`, `memory` и `facts` показывают объём **после** существующих
ограничений контекста. Заголовок текущего контекста измеряется отдельно.
Сумма размеров равна длине собранного промпта. Это символы, не токены и
не прогноз стоимости API. Текст с похожим заголовком внутри вложения не
создаёт новую запись карты: границы задаёт код, а не разбор текста.

Измерения создаются оценочным экземпляром движка, очищаются перед каждым
ходом и не хранятся в рабочем движке. Текст блоков, отпечатки личных сведений
и ключи в карту не включаются; обычные серверные логи ею не дополняются.
Сам оценочный отчёт по-прежнему содержит синтетические сообщения сценариев
и в реальном режиме ответы модели. Его сохраняют локально в игнорируемой
`.tmp`, не публикуют автоматически. Наборы ограничений и бюджет прежние.

## Границы проверки

Неизменяемые сборки не разделяют содержимое между запросами. Тесты сверяют
16 прежних SHA-256, непрерывность карты и размеры её частей, выбор тематических
блоков, ограничения динамического контекста и очистку измерений между ходами.
Бесплатный прогон всех 36 базовых сценариев сверяет размеры карт с запросами
перехваченного транспорта, без обращения к модели.

Карта не ищет смысловые противоречия автоматически и не доказывает качество
ответов. Она показывает, что реально собрало приложение, чтобы следующую
правку можно было проверить предметно. Манера речи, примеры и правила RP
на этом этапе не меняются; прежние эталоны не пересняты.

Дополнительно перед выпуском старые методы из предыдущей ревизии и новая
сборка сравнены на 58 синтетических ходах: 110 перехваченных запросов
совпали по текстовым отпечаткам и размерам. Это бесплатная проверка
эквивалентности запросов, а не новое измерение ответов модели.
