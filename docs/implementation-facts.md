# Факты о реализации и предложения изменений

Справка о реализации формируется приложением из текущих настроек и версии Python.
Она различает код Telegram-бота (Python, aiogram), хранение состояния/памяти (SQLite),
внешний API модели и личность, заданную промптами и логикой приложения. Настроенный
провайдер и имя модели известны; веса, внутреннюю архитектуру и историю замен
из одной строки настройки вывести нельзя. Это уточнение не отменяет известные факты.
Ключи и полный адрес endpoint в справку не передаются.

Технический вопрос «на чём ты создан» получает подробную справку, сохраняя личность.
Только для этого ответа старые RP-ремарки не задают сцену; сама настройка RP сохраняется.
Краткий перечень возможностей также содержит основные сведения о стеке.

Для своего разрешённого личного архива Дельта уже может сам вызывать `search_dialogue`,
когда нужны старые реплики; отдельная команда пользователя не обязательна. Это поиск
по сохранённым данным, а не весь архив в каждом контексте и не доступ к чужим чатам.

`/code_review` может предложить небольшую правку в блоке unified diff. Приложение
проверяет один существующий разрешённый файл на блок, точное совпадение контекста,
номера и размеры фрагментов. Неизвестные пути, скрытые секретные строки, неверные
фрагменты и обрезанные блоки не выдаются как готовая правка. Допускается до трёх
предложений, по 200 строк/12 000 символов; сам отчёт дополнительно ограничен по длине.

Предложение проверяется по обезличенному снимку исходника. Если его структура
сохранена, новый текст проходит `ast.parse` без импорта и исполнения. Когда маскирование
нарушило структуру снимка, синтаксис помечается как непроверенный. Сверка не означает
успешного применения к Git, запуска тестов или правильности поведения. Администратор
может обсудить diff с разработчиком; бот не получает право применять его сам.
