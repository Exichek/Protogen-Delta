# Аудит контекста и токенов, 8 октября 2026

Проверены сборка запросов и агрегированные usage-метрики текущего рабочего
контейнера. Содержимое чатов, профилей, промптов пользователей и API-ключи
не включены в отчёт. Метрики относятся к этому контейнеру после его запуска,
а не ко всему выбранному периоду аккаунта на скриншоте.

## Что передаётся

Основной системный промпт отправляется при каждом ответе. Все его дополнительные
секции одновременно в обычный разговор не включаются: лор выбирается по теме,
описание базового тела — по теме внешности, RP-секции — при активном RP.
Выбранный пользовательский облик включается в динамическое состояние каждого
ответа, чтобы не возвращались несовместимые признаки базового персонажа.

| Секция | Знаков в файле |
|---|---:|
| core | 16 681 |
| protogen_lore | 12 098 |
| body | 21 350 |
| rp | 14 110 |
| furry_species_reference | 5 272 |
| mood_classification | 3 764 |
| insult_classification | 3 929 |

Без динамических дополнений обычное «Привет» получает 16 681 знак.
Базовый RP — 64 245 знаков (core + lore + body + rp).
RP с пользовательским обликом — 36 067 знаков (core + species + rp);
внешность добавляется отдельно, базовые body/lore исключены.
Это измерение символов, не оценка токенов по соотношению символ/токен.

В API уходит до четырёх последних пар сообщений и краткое содержание более
ранних ходов до 2000 знаков. Для живой истории установлен бюджет 8000 знаков,
но один последний большой ход сохраняется целиком и может превысить его.
Полная SQLite-история в каждый запрос не отправляется. Эпизодическая память
ограничена 2000 знаками, факты пользователя — 7000, динамическое состояние —
4000. Факты и личная память исключены из групповых запросов.

Обычно на реплику приходится два API-запроса: объединённая классификация
настроения/оскорбления и основной ответ. Извлечение фактов выполняется только
при подходящем явном сообщении. Инструменты могут добавить запросы; назначение
облика картинкой использует два отдельных визуальных прохода.
Скачивание видео, /e6 и Whisper не вызывают языковую модель для этой работы.

Показатель 1,46 млн на скриншоте включает повторно переданный и кэшированный

отправку контекста; запрос должен передавать совпадающий префикс.
Основание: [DeepSeek Context Caching](https://api-docs.deepseek.com/guides/kv_cache/).
Расход $0.15 со скриншота не пересчитывался на частичный срез контейнера.

## Вывод и следующий этап

Повторяющийся контекст действительно велик. Главные источники — core,
статические RP/body/lore и отдельная классификация каждой реплики.
Облик и история добавляют объём, но вся база памяти или весь лор в каждый
обычный вопрос не отправляются. Значительная часть входа уже попадает в кэш.

Рациональные кандидаты для следующей оптимизации: убрать дубли правил из core,
сократить классификацию с сохранением различения агрессии/цитат/дружеского мата,
выбирать детали body/lore для RP по необходимости, убрать полный справочник
видов из каждого хода RP с уже установленным обликом. Отдельно нужен явный
предел последнего большого хода истории. Изменение расположения стабильных
и динамических частей следует оценивать по cache hit/miss и фактической цене.

Промпты личности, память и количество ходов этим аудитом не изменены.
Сокращение должно проверяться на сохранении голоса Дельты, личных фактов,
границ и связности RP; уменьшение числа токенов само по себе этого не доказывает.

После этого среза добавлены отдельный стиль обычного разговора в 18+ и
[подтверждённые сведения о доставке и RP-персонаже](creator-messages-and-rp-profile.md).
Журнал не передаётся целиком: его блок ограничен 2000 знаками и подключается
по вопросу об отправке или первой реакции на новую доставку. Описание
RP-персонажа вне сцены передаётся по прямому вопросу, не в каждый обычный ход.
Разговорный стиль подключается только в обычном 18+ чате. Метрики выше
относятся к предшествующему срезу и не оценивают расход после этих изменений.
