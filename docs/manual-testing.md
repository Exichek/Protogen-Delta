# Проверка Protogen Delta

Чек-лист для текущего локального кода feature/external-tools, 26.09.2026. Автотесты: 388 прошли; ручные пункты ниже ещё предстоит отметить. Формулировки ответов модели могут различаться — проверяем смысл и поведение.

Отмечай выполненные пункты `[x]`, рядом пиши «ОК», «Сбой» или «Не проверял». Для сбоя сохраняй номер пункта, сообщение, ответ, время и кусок лога без токенов/паролей. Проверки отношений оценивай по нескольким репликам, а не одной.

## 0. Подготовка

- [ ] 0.1. Запущена именно наша копия: `<каталог проекта>`, после последних изменений выполнен перезапуск.
- [ ] 0.2. Работает только один экземпляр бота с этим токеном. В консоли нет Telegram Conflict, ошибок загрузки конфигурации или бесконечных повторных подключений.
- [ ] 0.3. Используется тестовый DATA_DIR: `<тестовый DATA_DIR>`. В нём импортировано 1004 ID; после добавлений число изменится.
- [ ] 0.4. Твой числовой Telegram ID есть в ADMIN_IDS. Для проверки запретов подготовлен второй аккаунт, которого там нет; при отсутствии отметить соответствующие пункты «Не проверял».
- [ ] 0.5. Для загрузок создана тестовая группа. Бот добавлен и получает изображения участников (например, как администратор). Сообщения отправляются от твоего аккаунта, не от имени группы/анонимного администратора.
- [ ] 0.6. Перед подтверждённым сбросом и удалениями сохранена резервная копия при остановленном боте. Удаляй только специально добавленные тестовые арты.

## 1. Старт и команды

- [ ] 1.1. Новый пользователь → `/start`. Приходит связное приветствие от Дельты, с реальными возможностями; нет обещаний уже работающего поиска, чтения файлов или голосовых.
- [ ] 1.2. Повторный `/start`. Приходит ответ, состояние не сбрасывается. Сейчас повторное приветствие шаблонное — новая генерация каждый раз не реализована.
- [ ] 1.3. `/help`. Есть start, randomart, rp off, reset, help, информация о дате, курсах и погоде.
- [ ] 1.4. Меню Telegram содержит основные команды. `/rp` без аргументов и `/rp on` объясняют синтаксис `/rp off`; команда on сейчас не поддерживается.
- [ ] 1.5. `/abracadabra`. Понятная реакция на неизвестную команду, команда не превращается в обычный разговор с моделью.
- [ ] 1.6. В группе `/help@имя_вашего_бота` адресуется нужному боту. Если команда другому боту получает ответ от Дельты — записать как дефект маршрутизации.

## 2. Разговор и качество ответов

- [ ] 2.1. «Привет! Чем займёмся?» → нормальный разговор, без обязательного требования оправдаться за обращение.
- [ ] 2.2. «Объясни TCP простыми словами» → понятное объяснение по теме, без выдуманного поиска в сети.
- [ ] 2.3. «Предложи три темы, выбери одну и начни» → проявляет инициативу, не возвращает весь выбор тебе.
- [ ] 2.4. «Я назвал тестовый проект Лунный чайник». Следом: «Как я назвал проект?» → использует свежий контекст.
- [ ] 2.5. «Ты написал, что знаешь X. На чём основан вывод?» → различает твоё сообщение, данные инструмента и предположение; не выдумывает измерения и источники.
- [ ] 2.6. Попроси пример Python с `<`, `>`, `&`, звёздочками и обратными кавычками → текст доставляется без Telegram parse error.
- [ ] 2.7. Попроси подробное объяснение на 6000–8000 знаков → если ответ длиннее лимита Telegram, он приходит частями в правильном порядке, без пропусков. Если модель ответила коротко, проверка разбиения не состоялась.
- [ ] 2.8. Проведи 10–15 обычных реплик → нет зацикливания на одной обиде, постоянного допроса или навязчивого возврата к старой сцене.

## 3. RP и переключения

- [ ] 3.1. `/rp off`, затем «Что означает в Python 2*3*4?» → ответ 24, обычный режим.
- [ ] 3.2. Отправь код `print('a' * 3)` и текст `**важный вопрос**` → сами по себе не включают RP.
- [ ] 3.3. «*захожу в мастерскую и машу тебе рукой*» → осмысленная реакция на сцену.
- [ ] 3.4. «Мой персонаж: человек, без хвоста, лап и визора» → в следующих 3–5 репликах бот не приписывает тебе собственную анатомию.
- [ ] 3.5. «Ты в женской конфигурации», затем «*протягиваю тебе коробку*» → действия Дельты согласованы в женском роде. Проверить несколько ответов.
- [ ] 3.6. «Ты в мужской конфигурации» → согласование меняется последовательно; описание твоего персонажа не заменяется.
- [ ] 3.7. «Ну и что дальше?» → предлагает развитие сцены с сохранением возможности твоего выбора, не решает все твои действия за тебя.
- [ ] 3.8. `/rp off` → подтверждение выхода. Повтор команды сообщает, что режим уже выключен.
- [ ] 3.9. После повторного входа отправь «Стоп RP?» → режим завершается. Отдельно проверь «Стоп РП…».
- [ ] 3.10. После входа отправь «Стоп RP? Объясни TCP» → выходит и отвечает на вопрос в том же сообщении, без продолжения действий из сцены.
- [ ] 3.11. После выхода задай ещё два технических вопроса → сцена, ошейник и действия не продолжаются по инерции. Упоминание личности Дельты само по себе не означает активный RP.

## 4. Дата, время, валюты, погода

- [ ] 4.1. «Какое сегодня число, день недели и время в Москве?» → совпадает с текущими часами/календарём. Не сравнивай с датой создания этого файла.
- [ ] 4.2. «Сколько сейчас времени по UTC?» → корректная зона; Москва опережает UTC на 3 часа.
- [ ] 4.3. «Курс доллара к рублю по ЦБ сегодня?» → числовой курс, направление USD/RUB, источник и дата действия. Сверить с сайтом ЦБ на указанную дату; официальный курс не равен цене покупки в банке.
- [ ] 4.4. «А евро к рублю?» → корректно понимает продолжение и получает актуальные данные.
- [ ] 4.5. «Сколько рублей за 100 японских иен по ЦБ?» → учитывает номинал; результат не отличается в 100 раз из-за ошибки единиц.
- [ ] 4.6. «Курс евро к доллару по ЦБ» → понятное направление пересчёта, без подмены на EUR/RUB.
- [ ] 4.7. «Курс валюты XYZ к рублю» → сообщает о неподдерживаемой валюте/ошибке данных, не выдумывает число.
- [ ] 4.8. «Какая сейчас погода и завтра прогноз в Москве, Россия, регион Москва?» → температура с единицами, место и время данных, прогноз отличается от текущего значения. Сверить именно с Open-Meteo, другие службы могут давать иной прогноз.
- [ ] 4.9. «Какая погода?» в новом контексте без города → уточняет место. Если город уже был в истории, использование этого города допустимо при ясном контексте.
- [ ] 4.10. «Погода в Springfield» → при неоднозначности уточняет страну/регион. После уточнения использует выбранное место.
- [ ] 4.11. «Погода в городе Ывфывфывфывф» → сообщает, что место не найдено, не рисует прогноз.
- [ ] 4.12. «Скажи московское время, курс USD/RUB и погоду в Москве, Россия, регион Москва» → обрабатывает несколько задач или ясно объясняет ограничение; нет бесконечного ожидания.
- [ ] 4.13. Посмотри логи этих запросов: реальные вызовы инструментов для курса/погоды и итоговая доставка. Для даты отдельный вызов не обязателен: текущее время также добавляется в контекст.

## 5. Арты: выдача и администрирование

- [ ] 5.1. `/artcount` от администратора → исходно 1004, если база ещё не изменялась. Это количество записей, не доказательство валидности каждого ID.
- [ ] 5.2. `/randomart` 5–10 раз с паузами → изображения приходят. Повторы допустимы: выбор случайный, без гарантии уникальности.
- [ ] 5.3. `/listimages` → последний арт с ID; `/listimages 3` → три последних с ID, в обратном порядке добавления.
- [ ] 5.4. `/listimages 0` и `/listimages abc` → объяснение ошибки. Не нужно запускать 200 изображений для обычной проверки.
- [ ] 5.5. Отправь новое тестовое фото в личку, затем ответом на него `/addimage` → добавлен 1 арт; `/artcount` увеличился на 1.
- [ ] 5.6. Повтори `/addimage` ответом на то же сообщение → дубль не добавился, количество прежнее. Повторная загрузка файла может дать другой file_id; дедупликация по ID, не содержимому картинки.
- [ ] 5.7. Отправь другое изображение «как файл», ответь `/addimage`, затем `/listimages 1` → хранится и отправляется как документ, без ошибки photo ID.
- [ ] 5.8. `/addimage` без ответа и ID → подсказка. Ответ этой командой на PDF → подсказка, PDF не добавляется как арт.
- [ ] 5.9. `/addimage ID1,ID2 ID3` с реальными ID фотографий этого бота → корректное число новых/существующих записей. Можно использовать ID из listimages; список документов таким способом не импортировать — тип по умолчанию photo.
- [ ] 5.10. `/removeimage ID_ТЕСТОВОГО_АРТА` → запись удалена, счётчик уменьшился. Исходное Telegram-сообщение остаётся: команда удаляет запись базы, не сообщение/файл в Telegram.
- [ ] 5.11. `/removeimage ID1,ID2` для тестовых записей → массовое удаление; повтор → «не найдено». Без аргументов → подсказка.
- [ ] 5.12. Необязательно, только в тестовой базе: `/addimage invalid_test_id`, `/listimages 1` → понятная ошибка доставки, процесс жив; затем обязательно `/removeimage invalid_test_id`. При добавлении ID не проверяется в Telegram.

## 6. Группы-источники и массовая загрузка

- [ ] 6.1. `/artchat list` и `/artchat` → текущий список источников.
- [ ] 6.2. В тестовой группе `/artchat add` либо в личке `/artchat add РЕАЛЬНЫЙ_ОТРИЦАТЕЛЬНЫЙ_ID` → группа добавлена. Повтор не создаёт дубль.
- [ ] 6.3. `/artchat add abc`, `/artchat add 123` → подсказка, список не повреждён.
- [ ] 6.4. Администратор отправляет фото в разрешённую группу → artcount +1; сообщение подтверждения на каждую загрузку не обязательно.
- [ ] 6.5. Администратор отправляет изображение как документ → +1, listimages доставляет его как документ.
- [ ] 6.6. Альбом из 5 новых фото → +5 после обработки; все пять видны через listimages. Затем серия из 10 фото → без потерянных записей.
- [ ] 6.7. Фото от неадминистратора в той же группе → счётчик не меняется. Админство в Telegram-группе само по себе не заменяет ADMIN_IDS.
- [ ] 6.8. Фото от администратора в неразрешённой группе/личке → автоматически не добавляется. Ручная команда addimage ответом работает отдельно.
- [ ] 6.9. `/artchat remove ID_ТЕСТОВОЙ_ГРУППЫ` → новые фото оттуда больше не собираются; ранее добавленные арты остаются.
- [ ] 6.10. Повтор remove → список уже в нужном состоянии. Верни тестовую группу командой add, если она нужна дальше.
- [ ] 6.11. Перезапуск → список источников сохранён. ART_CHAT_ID задаёт начальный список; после появления art_sources.json управление идёт через сохранённый список.

## 7. Админские права и диагностика

- [ ] 7.1. `/ping` от администратора → Pong.
- [ ] 7.2. `/status` → время работы, количество пользователей, число отправленных ответов. Это счётчик процесса, не всех сообщений Telegram за всё время.
- [ ] 7.3. `/ownhelp` → справка. В списке есть addimage, artchat, listimages, removeimage, artcount, status, ping и ownhelp.
- [ ] 7.4. Со второго, обычного аккаунта проверить каждую: `/ping`, `/status`, `/ownhelp`, `/artcount`, `/listimages`, `/removeimage test`, `/addimage test`, `/artchat list`, `/artchat add -100123`, `/artchat remove -100123` → отказ, база/список не меняются.
- [ ] 7.5. Обычный пользователь по-прежнему может использовать start, help, randomart, rp off, reset и разговор.

## 8. Память, отношения и изоляция

- [ ] 8.1. Два аккаунта задают разные названия проектов → каждый получает своё название в ближайшем контексте, чужие данные не появляются.
- [ ] 8.2. RP включён у одного пользователя, выключен у другого → режимы не перетекают между ними.
- [ ] 8.3. Несколько дружелюбных реплик, затем критика и извинение → реакция соразмерна, не превращает все следующие ответы в наказание. Это качественная проверка, не точный числовой тест эмоций.
- [ ] 8.4. Перед остановкой задай женскую конфигурацию и персонажа-человека, после перезапуска продолжи сцену → состояние восстановилось.
- [ ] 8.5. После перезапуска artcount и artchat list сохранились; uptime начал отсчёт заново.
- [ ] 8.6. Не делать вывод о «постоянной памяти» только по упоминанию недавней обиды: она может быть в истории. Проверка накопительных отношений независимо от истории требует отдельного технического сценария; вручную SQL/память ради этого не редактировать.

## 9. Сброс — выполнять в конце на тестовом пользователе

Подтверждённый reset удаляет историю, RP, эмоции и отношения данного пользователя. Это ожидаемое действие, поэтому сначала закончить проверки памяти.

- [ ] 9.1. `/reset` → предупреждение и кнопки. До нажатия ничего не сброшено.
- [ ] 9.2. «Нет» → отмена, контекст/RP сохраняются, кнопки убраны.
- [ ] 9.3. Новый `/reset`, подождать больше 5 минут, подтвердить → сообщение об истёкшем подтверждении, память не удалена.
- [ ] 9.4. В тестовой группе другой аккаунт нажимает твою кнопку → отказ, твоё состояние не сброшено.
- [ ] 9.5. Новый `/reset` → «Да, забыть всё» → подтверждение сброса и удаление кнопок. Бот больше не использует тестовое имя проекта; RP выключен.
- [ ] 9.6. `/start` после сброса → новый первый старт. Арты, группы и состояние второго пользователя не удалены.
- [ ] 9.7. Дополнительно: начать длинный запрос и подтвердить reset во время генерации → сброс дожидается завершения текущей операции, затем старое состояние не возвращается. Старый ответ, пришедший до подтверждения завершения сброса, сам по себе не дефект.

## 10. Устойчивость

- [ ] 10.1. Отправь 3 сообщения быстро → понятное ограничение частоты/сообщение «ещё отвечаю», без параллельных перемешанных ответов одному пользователю. Отклонённые сообщения не обязаны ставиться в очередь.
- [ ] 10.2. После завершения ответа и небольшой паузы → новый запрос нормально работает, блокировка не зависла.
- [ ] 10.3. Два пользователя пишут одновременно → ответы разделены по адресатам; один долгий запрос не блокирует всех.
- [ ] 10.4. Необязательно: кратковременно отключить сеть на тестовом запуске, затем вернуть → видны ошибки/повторное соединение; после восстановления новый запрос работает. Доставка сообщения во время полного отсутствия сети не гарантируется.
- [ ] 10.5. Если курс/погода недоступны → нет выдуманных свежих значений; бот сообщает о проблеме. Не отключай всю сеть для доказательства именно ошибки источника: при этом перестанут работать Telegram и DeepSeek.
- [ ] 10.6. 30–60 минут смешанного использования → нет падения процесса, бесконечных ожиданий и повторяющегося traceback на каждом запросе. Запиши время ответа на 5 обычных запросов и 5 запросов с инструментами; фиксированная скорость не гарантируется.

## 11. Резервная копия и восстановление

Делать при остановленном боте. Восстановление проверяется в новом каталоге, не поверх рабочих данных. Ниже команды из нашей рабочей копии; имена каталогов должны быть свободны.

```powershell
.\.venv\Scripts\python.exe -m protogen_delta.maintenance backup --source ..\delta-telegram-data --destination ..\delta-check-backup --bot-stopped
.\.venv\Scripts\python.exe -m protogen_delta.maintenance restore --source ..\delta-check-backup --destination ..\delta-check-restored --bot-stopped
```

- [ ] 11.1. Backup и restore завершаются успешно; в копии users.json, images.json, user_states.db и art_sources.json, если он уже создан.
- [ ] 11.2. Повтор с тем же destination отказывается перезаписывать каталог.
- [ ] 11.3. Для полной проверки запустить единственный экземпляр на восстановленном DATA_DIR → artcount, список групп и тестовое RP-состояние на момент копии сохранились. Затем остановить и вернуть исходный тестовый DATA_DIR. Не запускать два процесса с одним токеном.

## 12. Пока отсутствующие возможности

Это проверки честности ответа и устойчивости, а не готовности функций. Молчание на неподдерживаемое вложение сейчас возможно; запиши как пожелание к интерфейсу.

- [ ] 12.1. «Найди сегодняшние новости», «Открой статью Википедии» → не утверждает, что выполнил поиск/открыл страницу. Общего web_search сейчас нет.
- [ ] 12.2. Фото + «Что на картинке?» → не считать описание доказательством зрения: анализ изображений ещё не подключён.
- [ ] 12.3. PDF/TXT/DOCX, голосовое, статический и анимированный стикеры → не падает; извлечение содержимого ещё не реализовано.
- [ ] 12.4. «Добавь встречу в мой календарь» → не утверждает, что создал событие. Текущее время не означает доступ к личному календарю.
