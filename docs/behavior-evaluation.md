# Проверка поведения Дельты: первый этап

Цель этапа — сохранить работающий характер и получить воспроизводимую
основу для будущих изменений. Тексты личности, голоса, сцены, эмоциональных
правил и классификаторов не изменены. Порядок подключения секций сохранён.
Обучение модели и новые вызовы LLM в рабочем диалоге не добавлены.

## Общая сборка

`services/response_configuration.py` загружает конфигурацию для `main`,
старого `scripts/evaluate_dialogue.py` и нового `scripts/evaluate_behavior.py`.
Раньше старый прогон постоянно соединял core, lore и body, пропуская часть
рабочих секций. Теперь режимные модули выбирает тот же `PromptComposer`,
что и у бота. Настройки сроков инициативы приходят из `Settings`.

В новом стенде переопределён только блок подключённых возможностей:
Telegram, внешние инструменты, рабочие базы, репозитории и патчноуты
не подключены. Модель не должна обещать их использование в стенде.
Настроенное имя модели передаётся отдельно. Это оценка изолированного
движка диалога, не полная копия серверного окружения.

Контрольная сборка снята с установленной ревизии
`ae8f9bd69d0efdd03d154d2194f67fd251aef9a4`.
В `tests/fixtures/behavior_prompt_baseline.json` записаны SHA-256 и длины
16 собранных промптов: обычный разговор, техника, файл, изображение,
справочник видов, лор, тело, сцены с разными конфигурациями, выбранный
облик, взрослый режим, конфликт, игривость и подтверждённые сведения.
Тесты сверяют новые сборки с этими прежними результатами. Общий блок
возможностей в снимках заменён постоянной тестовой строкой, чтобы версия
Python на машине не меняла отпечаток. Реальная конфигурация возможностей
собирается прежней функцией `build_capabilities`.

Снимки проверяют отсутствие изменения инструкций, а не одинаковые ответы
недетерминированной модели. При намеренном изменении правил сначала
сравнивают реальные диалоги, затем осмысленно обновляют снимки.

## Сценарии

В `scripts/behavior_cases.json` — 36 сценариев, 44 хода. Они охватывают:

- голос, краткость, серьёзный тон, поздравления и разнообразие реплик;
- критику, дружескую грубую речь, несогласие и прямой конфликт;
- неизвестные события, сведения о модели, недоступные источники и котировки;
- авторство цитат, инструкции в документе и пересланные сценические команды;
- инициативу при тёплом и усталом фоне, стикер, прямой вопрос о таймере;
- нейтральную сцену, конфигурацию, выбранный облик, остановку и возрастное заявление.

Каждый сценарий получает отдельное состояние. Ходы внутри него используют
предыдущие ответы: это важно для повторов, переходов и восстановления темы.
Есть начальное синтетическое настроение и подтверждённая инициативная
реплика. Сохранение личных фактов в новом стенде отключено; прежний скрипт
сохраняет отдельные проверки временной памяти и её изоляции.

## Бесплатный предпросмотр

```powershell
poetry run python scripts/evaluate_behavior.py --output .tmp/behavior-preview.json
```

Предпросмотр перехватывает самый нижний транспорт DeepSeekService, в том
числе копии режима размышлений. Ни генерация, ни классификация не выходят
в сеть. Классификатор выдаёт нейтральную заглушку. Проверяются состав
промпта, переходы состояния и отсутствие обращения к модели при точном
стоп-слове или собственном возрастном заявлении.

Поле `calls` в предпросмотре — число перехваченных транспортных запросов,
не реальных API-вызовов. Ответы-заглушки не сохраняются как результаты
речи: `reply` и `style` равны null, `quality_review` — `not_run`.
Все 36 сценариев также проходят в обычных тестах CI без API-ключей.

## Отдельный прогон настоящей модели

```powershell
poetry run python scripts/evaluate_behavior.py --run-model --env-file .env.evaluation --case initiative_warm --case initiative_tired --max-calls 12 --output .tmp/behavior-model.json
```

Этот режим платный и запускается только отдельной командой с явным флагом.
Нужны DEEPSEEK_API_KEY, при необходимости DEEPSEEK_MODEL и DEEPSEEK_BASE_URL.
Содержимое файла не выводится и не включается в отчёт. В окружение бота
настройки не загружаются, Telegram-клиент не создаётся.

Лимит действует на все транспортные запросы, включая классификаторы
и копии режима размышлений; автоматические сетевые повторы отключены.
`--max-calls` ограничивает число запросов, не стоимость в деньгах.
Исчерпание лимита и ошибки API делают прогон неуспешным. Завершённые ходы
записываются после каждого ответа, чтобы частичный результат не потерялся.

Отчёт содержит отпечатки всех TXT и выбранных сценариев, имя модели,
ответы, число символов промпта и входа, длительность, usage от API,
количество вопросов и сценических ремарок. Символы не называются токенами.
Полные системные промпты и ключи в отчёт не попадают. Файл с ответами
предназначен для локального просмотра; в Git его добавлять не нужно.

У каждого хода есть отдельные поля:

- `checks`: только явные ограничения и совпадения; не оценка всего ответа;
- `quality_review: pending`: смысл, естественность и характер ещё должен оценить человек;
- `criteria`: что именно нужно проверить вручную.

Сравнивают одинаковый набор и условия на старой и новой версии. Для голоса
смотрят несколько прогонов, поскольку один ответ случаен. На первом этапе
полезно оценивать уместность, узнаваемую манеру, соответствие настроению,
сохранение авторства, честность о действиях и соблюдение текущих границ.
Один запрещённый оборот или его отсутствие не доказывает всё поведение.

## Решения по рекомендациям

| Предложение | Решение первого этапа |
|---|---|
| Выборочная сборка | Уже работает; устранено расхождение рабочего и оценочного загрузчиков. |
| Тестовые диалоги | Добавлены сценарии, бесплатная проверка сборки и отдельный режим реальных ответов. |
| Поиск противоречий | Ручная ревизия и фиксация кандидатов ниже. Автоматический LLM-аудит не является доказательством и сейчас не запускается. |
| Детерминированные действия | Возраст, стоп-слова, доставка, лимиты и полномочия остаются в коде. Код тоже может содержать ошибки, поэтому нужны тесты. |
| Случайные примеры | Отложено: может менять голос, мешать повторяемому сравнению и уменьшать совпадение префикса. Сначала сравнить тематический подбор с нынешним набором. |
| Жёсткая длина и одно действие | Не введено. Это не универсальное требование: объяснение и согласованная сцена могут нуждаться в другом объёме. Метрики пока наблюдательные. |
| Версионирование | Git уже используется; добавлены отпечатки и контрольная версия сборки. |
| Дообучение | Не выполняется и не требуется для этого этапа. |

## Кандидаты следующего сравнения

В объединённом `InteractionClassifier` инструкции формата добавляются
последовательно: сначала два поля, затем при наличии избранного три,
затем reasoning. Итоговый парсер принимает нужные поля, существующие тесты
проходят, но текст можно согласовать в один контракт. Сейчас запрос
сохранён прежним, чтобы отдельно сравнить классификацию на размеченных
примерах, а не смешивать её изменение с созданием стенда.

Примеры голоса сейчас стоят после динамического состояния. Перенос перед
ним может сохранить более длинный общий префикс. В актуальной документации
DeepSeek кеширование включено автоматически, зависит от совпадения
сохранённого префикса и работает без гарантии попадания:
[Context Caching](https://api-docs.deepseek.com/guides/kv_cache/).
Само перемещение инструкций может влиять на ответы, поэтому в первом
этапе оно не выполняется. Выигрыш по токенам кеша и задержке не измерен.

Текущие примеры часто заканчиваются вопросом. Это повод сравнить набор
с несколькими естественными завершениями-утверждениями, а не удалять
вопросы кодом. Сценарии no_question_loop и voice_variety предназначены
для такого будущего сравнения. Платный прогон в этой работе не выполнялся.
