# Сравнение визуальных моделей

Скрипт `scripts/compare_vision.py` запускает существующий `AppearanceAnalyzer`
через независимые клиенты DeepSeek и Gemini. По умолчанию выбирается только DeepSeek; для сравнения двух моделей передать `--provider both`. Рабочий бот продолжает
использовать DeepSeek; скрипт не читает SQLite, не отправляет сообщения в
Telegram и не меняет сохранённый облик или RP-профиль.

## Подготовка

Ключ Gemini создаётся в [Google AI Studio](https://aistudio.google.com/apikey).
Сохранить его одной строкой в `.secrets/gemini-api-key.txt` или передать через
переменную окружения `GEMINI_API_KEY`. Папка `.secrets` исключена из Git.
DeepSeek берётся из локального `.env`. Ключи не попадают в отчёт или вывод.

Для нового проекта выбран `gemini-3.8-flash`; модель можно заменить аргументом
`--gemini-model`. Используется уже установленный OpenAI SDK и официальный
[совместимый API Gemini](https://ai.google.dev/gemini-api/docs/openai), без новой
зависимости. Доступ и квота конкретного проекта проверяются при первом запросе.
На [бесплатном тарифе](https://ai.google.dev/gemini-api/docs/pricing) Google может
использовать запросы и ответы для улучшения продуктов. Скрипт не подключает
оплату и не переключает тариф проекта.

Манифест — JSON-массив от одного до трёх примеров:

```json
[
  {
    "name": "hair",
    "images": ["art.png", "head.png"],
    "caption": "Два референса одного персонажа. Опиши его постоянную внешность.",
    "checks": ["Волосы отдельно от шерсти", "Цвет видимого глаза"]
  }
]
```

Пути к картинкам разрешаются относительно манифеста. В одном примере допустимы
до трёх изображений одного персонажа. Сначала убрать из скриншотов интерфейс,
старые описания и подсказки. Проверки `checks` предназначены человеку: они
записываются в отчёт, но не передаются модели. Арты и отчёты хранить в `.tmp`.

## Запуск

```powershell
.venv/Scripts/python.exe scripts/compare_vision.py --manifest .tmp/vision-comparison/cases.json --output .tmp/vision-comparison/plan.json
.venv/Scripts/python.exe scripts/compare_vision.py --manifest .tmp/vision-comparison/cases.json --output .tmp/vision-comparison/results.json --run
```

Без `--run` выполняется только локальная подготовка без запросов к API.
Для текущей работы с DeepSeek ключ Gemini не требуется. С `--run` каждое изображение проходит ту же подготовку, что загрузка облика:
полный кадр, JPEG до 1536×1536, удаление метаданных. При сравнении двух моделей подготовленные байты и
промпты одинаковы. Второй запрос включает наблюдения первого
прохода соответствующей модели, поэтому его входной текст естественно различается.
Внешние инструменты и история чата отключены.

Настройки воспроизводят текущий анализ облика: JSON для обоих проходов, до 4096
выходных токенов на проход, общий таймаут 50 секунд на два прохода. DeepSeek
работает с отключённым thinking и температурой 0; Gemini — с `reasoning_effort=low`, поскольку
thinking моделей Gemini 3 нельзя полностью отключить. Отдельный SDK-таймаут
запроса — 35 секунд. Это практическое сравнение конфигураций, а не сравнение
при идентичном внутреннем вычислительном бюджете.

Лимит — два запроса на пример, максимум шесть на поставщика. Повторы,
автоматическая починка JSON и fallback отсутствуют. При HTTP 401/403/404/429
сравнение останавливается: сначала исправить доступ, модель или квоту.
Повторный запуск с `--run` делает новые запросы; кеширования ответов нет.

## Оценка

Отчёт сохраняется после каждого результата. Он содержит ответы обоих проходов,
проверенное описание, вид и его происхождение, признак ограничения референса,
время, HTTP-код при ошибке и usage, если API его вернул. SHA-256 изображений и
системных промптов позволяют проверить одинаковый вход. Сырые исключения SDK,
ключи и содержимое HTTP-заголовков не сохраняются.

Сравнивать отдельно:

- узнаваемые детали: волосы, морда/визор, цвет глаз, покров и аксессуары;
- выдуманные или перепутанные признаки и пропуски;
- материал: шерсть, кожа, чешуя, металл — с учётом неоднозначности рисунка;
- постоянный облик отдельно от позы и выражения лица;
- корректность JSON и прохождение проверки каталога;
- время двух проходов и суммарные входные/выходные токены.

Названия вида без авторского подтверждения — гипотезы. Количество токенов у
разных моделей нельзя прямо сравнивать как деньги: отличаются токенизация,
обработка изображений, thinking и тариф. Качественный вывод делает человек по
арту и ответам; сам скрипт не объявляет победителя. Три примера — предварительная
проверка известных проблем, а не доказательство общего превосходства.

Переводить анализ картинок рабочего бота на Gemini стоит после получения и
оценки живых результатов. Разговор, память и RP для такого перевода менять не нужно.
