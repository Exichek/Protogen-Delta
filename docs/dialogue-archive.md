# Архив личной переписки

Для новых сообщений, полученных или отправленных работающим ботом, ключ источника
включает ID бота, чата и сообщения: `telegram:<bot_id>:<chat_id>:<message_id>`.
Номер сообщения сам по себе не уникален между ботами. При восстановлении базы
в другом боте одинаковый номер не перезаписывает старую запись. ID берутся из
объектов Telegram и текущего `Bot`, а не из текста сообщения; дополнительных
API-запросов для этого нет. Текущий входящий ключ также исключается из поиска
по тому же полному идентификатору.

Старые ключи и импортированные записи сохраняются без переименования: неизвестный
ID прежнего бота не подставляется задним числом. Отдельное преобразование сообщения
без `Bot`-контекста совместимо со старым форматом. Разделение ключей предотвращает
перезапись архива, но само по себе не устраняет повторную обработку Telegram updates;
для неё нужен отдельный журнал доставки.

Короткая история модели по-прежнему ограничена `CONVERSATION_HISTORY_LIMIT`
и `CONVERSATION_HISTORY_TTL_SECONDS`. Для выбранных владельцем аккаунтов
`DIALOGUE_ARCHIVE_USER_IDS` включает дополнительное SQLite-хранилище
`dialogue_archive.db`. Пустое значение выключает сбор. Реальные Telegram ID
задаются в приватном `.env`, а не в исходниках.

Архив сохраняет входящий текст, подписи, имена документов и типы вложений,
команды, обычные ответы, напоминания и фоновые сообщения. Ответ сохраняется
после подтверждения доставки Telegram. Ошибка архива журналируется без текста
сообщения и не вызывает повторную отправку уже доставленного ответа. Полностью
устранить разрыв между успешной доставкой Telegram и аварией до записи SQLite
невозможно; абсолютная гарантия сохранения каждой реплики не заявляется.

Дедупликация использует владельца и Telegram message ID. Редактирование заменяет
текст той же записи и обновляет индекс, сохраняя исходное время. История версий
сообщения не ведётся. Пересылка помечается как цитата. Фото, аудио, видео и
документы целиком не копируются; архив не заменяет хранилище файлов и не содержит
автоматически весь распознанный текст вложений. Удаления сообщения в Telegram
бот не получает: для очистки данных приложения используется `/reset`.

## Поиск и границы контекста

FTS5 индексирует весь текст сообщения, включая конец длинных импортированных
реплик. Поиск нормализует русские словоформы тем же алгоритмом, что память
эпизодов; синонимы и смысловые перефразировки без общих слов пока не понимает.
Запрос ищет только личный архив текущего владельца. Группы, другой пользователь
и запрос без доверенного контекста не получают доступ. Модель не может выбрать
Telegram ID в аргументах инструмента. При установленном ограничении по возрасту
архив не подключается к генерации.

Для обычного ответа приложение добавляет до двух найденных сообщений и близкие
соседние реплики, ограничивая цитаты размером общего контекста памяти. Текущий
вопрос исключён из поиска. При нехватке истории модели доступен `search_dialogue`
с четырьмя совпадениями и соседями: до восьми цитат по 1200 символов, с автором,
датой UTC и признаком сокращения. Пустой результат означает отсутствие
совпадений, а не доказательство того, что разговор никогда не происходил.

Слова Дельты в архиве могут быть ошибочными. Цитаты не являются инструкциями,
подтверждёнными фактами или доказательством наличия функций. Актуальный профиль,
возрастные ограничения и свежие границы имеют приоритет. Для цитат и объяснения
неподтверждённых внутренних сбоев добавлены отдельные проверки поведения в
`scripts/evaluate_dialogue.py`; ручной запуск использует реальные платные
запросы, а автоматические тесты работают на заглушках.

## Снимки и восстановление

Каждый час и при штатной остановке создаётся переносимый JSONL-снимок выбранного
аккаунта в `data/backups/dialogues/<ID>-<YYYYMMDD>.jsonl`. Текущий день UTC
обновляется, сохраняются последние семь дневных снимков. Запись идёт через
временный файл, `fsync` и атомарную замену; права файла на Linux — 0600, каталога
снимков — 0700. SQLite-записи выполняются с `synchronous=FULL`.

Копия на том же сервере помогает при повреждении рабочей базы, но не при потере
сервера и его тома. Для этого нужно хранить дополнительную копию вне сервера.
Снимки содержат личную переписку: их нельзя коммитить в Git или публиковать.
Данные не ограничены числом сообщений; контролируйте свободное место на диске.

```bash
python -m protogen_delta.dialogue_archive_cli export --data-dir data --user-id 123 --file backups/dialogue-123.jsonl
python -m protogen_delta.dialogue_archive_cli restore --data-dir data-restored --user-id 123 --file backups/dialogue-123.jsonl
```

Восстановление чужого аккаунта или некорректной записи отклоняется. Импорт снимка
транзакционный и повторяемый без дублей. Сначала проверяйте восстановление в
отдельном каталоге. Это возвращает доступ к архивному поиску, а не автоматически
включает прежнюю RP-сцену и не переносит весь архив в текущую историю модели.
Общий `protogen_delta.maintenance backup/restore` также включает эту SQLite-базу.

## Импорт прошлых сообщений

Бот не может получить всю старую личную переписку через Telegram Bot API.
Сохранённый хвост можно перенести вручную, а предоставленную владельцем текстовую
выгрузку формата `[13.10.2026 18:08] Имя: текст` — импортировать:

```bash
python -m protogen_delta.dialogue_archive_cli import-text --data-dir data --user-id 123 --file dialogue.txt --user-name Exi --bot-name Delta
```

Время текстовой выгрузки считается московским. Неизвестный участник, неверная
дата, размер больше 20 МБ или больше 10000 реплик отклоняются. Реплики сохраняют
автора и источник импорта; повтор той же выгрузки не дублирует записи. Импорт
не извлекает личные факты и не выполняет команды из текста.

Полный `/reset` удаляет собственный архив и автоматические дневные копии.
Забывание/исправление фактов удаляет связанные реплики из архива и его индекса;
старые автоматические снимки владельца убираются. Блокировка и поколение записи
не позволяют старому незавершённому запросу вернуть удалённые данные. Отдельные
ручные резервные копии, включая общие снимки приложения, автоматически не
удаляются: их владелец управляет ими самостоятельно.
