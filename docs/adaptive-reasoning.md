# Размышления для отдельного ответа

При `LLM_PROVIDER=deepseek` и `LLM_ADAPTIVE_THINKING=true` приложение может включить
размышления только для текущего сложного ответа. Обычный режим по умолчанию остаётся
быстрым (`LLM_DISABLE_THINKING=true`). В профиль пользователя выбранный режим не пишется.

Уже существующая общая классификация настроения и оскорблений дополнительно возвращает
`reasoning: true/false`. Разбор ошибки, доказательство, расчёт с условиями и сравнение
решений с ограничениями относятся к сложным задачам; приветствие, простой факт, перевод,
погода и RP остаются быстрыми. Старый JSON без этого поля поддерживается. Ошибка или
неверный тип поля не вызывают ещё одну классификацию. В явных просьбах «подумай»,
«проверь код», «докажи» есть локальная подстраховка; «без размышлений» отключает выбор.
Команды внутри цитат и блоков кода не переключают его. Как любая классификация,
автоматический выбор иногда может ошибиться.
Для короткого продолжения задачи классификатор получает предыдущий вопрос и ответ
из истории текущего диалога, до 1000 символов, отдельным полем. Эмоции и избранное
по-прежнему определяются только по новому сообщению.

Основной промпт, личность, история и правила безопасности сохраняются. Пользователь
получает итоговый ответ; внутренние размышления не отправляются в Telegram, не записываются
в историю и не выводятся в логи. Внутри одного цикла инструментов `reasoning_content`
передаётся обратно API, как требует [документация DeepSeek](https://api-docs.deepseek.com/guides/thinking_mode/).
Для старых ответов, у которых размышления не сохранены, передаётся пустое поле.

Для сложного ответа создаётся копия настроек клиента: до 8192 выходных токенов,
таймаут одного запроса 60 секунд, цикла инструментов 120 секунд, без автоматических
повторов SDK. Параллельный обычный разговор другого пользователя не переключается.
Именованный обязательный вызов инструмента выполняется с выключенными размышлениями,
поскольку DeepSeek не поддерживает этот `tool_choice` в режиме размышлений;
дальнейший анализ результатов снова использует их. Калькулятор и поиск сохраняются.

`/code_review` запрашивает размышления для аудита, когда этот режим разрешён настройкой.
Переводчик, инициативные сообщения и остальные служебные классификаторы автоматически
не переводятся в него. Для другого OpenAI-совместимого провайдера адаптивное включение
не применяется. `LLM_ADAPTIVE_THINKING=false` выключает эту возможность.

Выбор режима не добавляет отдельного API-запроса. Все реальные запросы и токены
по-прежнему учитываются в общей квоте пользователя. Размышления могут увеличить
время и стоимость ответа и не гарантируют отсутствие ошибок.
