# Ревизия проекта — 7 октября 2026

Проверены маршруты Telegram, ResponseEngine и классификаторы, SQLite/JSON и память, документы, изображения/анимация, аудио, видео, внешние инструменты, Mini App, права доступа, резервные копии, CI и Docker. Основа — develop после PR #65. Ревизия включает обзор кода, воспроизведение конкретных регрессий и доступное состояние сервера; она не заменяет длительный тест нагрузки и независимый аудит безопасности.

На старте контейнер занимал 231 МБ RAM, без перезапусков. В его текущих логах нет traceback, конфликтов polling и `database is locked`. На диске 31 ГБ свободно 8,4 ГБ (занято 73%). Docker сообщил 7,32 ГБ образов и 8,34 ГБ кеша; часть слоёв общая. После пересоздания контейнера ещё нет свежих метрик пользовательских LLM-запросов, поэтому средняя скорость и стоимость диалога здесь не оцениваются.

| Подтверждённая проблема | Исправление | Проверка |
|---|---|---|
| Кеш копировал все состояния перед проверкой устаревания | Обход только устаревшего префикса, без копии всего словаря | 10 000 свежих записей: посещена одна; прежние тесты блокировок сохранены |
| Очистка статистики сканировала таблицу без индекса; старое сообщение откатывало username | Индекс по `at`, обновление имени только по актуальному времени | План SQLite и сообщения, пришедшие не по порядку |
| XLSX мог обходить миллион пустых строк; файл не закрывался при ошибке | 5000 строк/128 столбцов на лист, 20 листов/20 000 строк всего, гарантированное закрытие и отметка частичного чтения | Настоящий XLSX с ячейкой XFD1048576, сбой итератора |
| DOCX/XLSX ограничивались только сжатым размером | До разбора проверяются 100 МиБ распакованного объёма, 32 МиБ на часть и 2000 ZIP-частей | Сжатый архив отклоняется до библиотечного парсера |
| Whisper мог запускать параллельный inference, отмена ожидания освобождала ресурс слишком рано | Один Whisper-worker, по два worker для документов и визуального декодирования; слот удерживается до конца потока | Отмена первого ожидания не запускает второй поток; ошибки освобождают слот |
| Расшифровка потребляла все сегменты, прежде чем обрезать текст | Генератор прекращается после лимита текста | Запрещающий дальнейшую обработку тестовый сегмент не читается |
| Число Telegram-обработчиков не было ограничено | До 32 обновлений одновременно | Интеграция запуска aiogram и полный набор маршрутов |
| Обычный чат не задавал предел ответа | 4096 токенов; обрезанный провайдером ответ отмечается | Запрос SDK и `finish_reason=length` |
| DNS при подключении мог отличаться от предварительно проверенного | Resolver проверяет фактические адреса; SOCKS получает проверенный IP, TLS — исходное имя сайта | DNS rebinding, LAN/link-local/mapped-IP, TLS/SOCKS и HTTPS |
| Удаление профиля могло подтверждаться словом из чужой цитаты | Требуется собственная явная просьба удалить сведения | Чужая цитата и «не забудь» не удаляют профиль |
| Групповой ответ не увеличивал счётчик | Учитывается успешный ответ, без записи в личную историю | Счётчик увеличивается, история остаётся пустой |
| Фоновый проход мог продолжаться после остановки | Проверки остановки перед генерацией/отправкой, две минуты на штатное завершение контейнера | Остановка в процессе генерации предотвращает дальнейшую отправку |
| Обновления кода переустанавливали библиотеки и копировали весь изменённый venv | Стадии зависимостей, wheel и установки небольшого пакета разделены | Реальная Docker-сборка и установленный пакет |
| Кеш файлов Whisper терялся при пересоздании контейнера | Том `whisper_models`, доступный непривилегированному пользователю | Запись в каталог кеша, совместимость compose |

Синтетический замер кеша: 50 000 свежих состояний, 200 проверок — 1,154 с до изменения и менее 0,001 с после. Это измерение одной операции кеша. Для оценки скорости реального диалога нужны метрики внешних запросов и обработки медиа.

| Следующее направление | Приоритет и основание | Предлагаемый результат |
|---|---|---|
| Изоляция лички и групп | Исправлено отдельным этапом: состояние по `(chat_id, user_id)` в `conversation_states`; личные данные не копируются | Регрессии разных групп/участников, `/rp off`, обликов, рестарта и полного reset во время доставки |
| Изоляция нативных парсеров | P1: потоки ограничены, но таймаут ожидания не завершает декодер. В PDF время проверяется между страницами | Worker-процессы с лимитами времени/памяти и чистым окружением для PDF/TGS/декодирования |
| Сокращение обращений к LLM | P2: обычная реплика делает два запроса классификации и запрос ответа; подходящие факты добавляют ещё один | Один JSON-классификатор настроения/оскорбления; сравнить токены и p50/p95 на одинаковых сценариях |
| Анализ музыки | P2: AudD, аудиомодель, локальные измерения и Whisper идут последовательно | Параллельные независимые шаги с отдельными отказами и общим бюджетом времени |
| Восстановление короткой истории | P2: профиль/настройки/эпизоды долговечны, последние ходы находятся в RAM | Ограниченное SQLite-хранилище с TTL, забыванием и сохранением только после подтверждённой доставки |
| Наблюдаемость | P2: `/health` подтверждает HTTP Mini App, а не связь polling с Telegram | Метка успешного polling, очереди, ошибки и время операций без пользовательского текста |
| Запуск при большой базе | P2: личные меню всех пользователей обновляются последовательно до старта HTTP/polling | Ограниченная фоновая синхронизация с сохранением возрастного доступа |
| Разделение ResponseEngine | P3: движок совмещает много задач; тесты часто меняют приватные поля | Сценарии ответа, память и облики с явными интерфейсами, постепенный перенос с контрактными тестами |
| JSON и Docker-хранение | P3: JSON переписывается целиком, хотя текущая база мала; Docker уже занимает заметное место | SQLite для крупных коллекций при подтверждённой нагрузке, политика хранения версий/копий |

Проверки используют фиктивных пользователей и временные базы, не рабочие данные. Перед обновлением создаётся резервная копия. Запросы, доставка, медиа и пополнение коллекции `/e6` сохраняют прежний код и проверяются сравнением файлов и существующими тестами.
