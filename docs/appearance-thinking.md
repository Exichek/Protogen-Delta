# Thinking при загрузке облика

Для официального провайдера DeepSeek оба прохода назначения облика получают
thinking.type=enabled и reasoning_effort=high. Это относится к картинке из
миниаппа и к явному назначению облика картинкой в чате. Обычный анализ
прикреплённой картинки, разговор, RP, классификаторы и память используют
прежний клиент с общей настройкой LLM_DISABLE_THINKING.

Клиент облика создаётся отдельно без изменения настроек основного сервиса.
Он использует ту же модель и общий сбор метрик, без внешних инструментов,
с JSON-ответом и лимитом 16384 токена на запрос. Температура не передаётся:
thinking её не поддерживает. Таймаут одного запроса — 60 секунд, повторов SDK
нет; общий бюджет двух проходов — 120 секунд, всей загрузки миниаппа — 150.
При ошибке анализа текущий сохранённый облик не заменяется.

Пользователь получает только content. reasoning_content не добавляется в
карточку, историю, следующий проход или логи. Количество проходов остаётся два.
Для других совместимых провайдеров специальные параметры DeepSeek не включаются.

Параметры сверены с [официальной документацией](https://api-docs.deepseek.com/guides/thinking_mode/).
Задержка и расход токенов могут увеличиться. Таблица с результатом 21/33 и
33/33 не содержит источника и не является измерением наших артов; рост точности
ещё предстоит подтвердить. Реальные API-пробы не выполнялись.
