# Чтение публичных GitHub-репозиториев

Присланная прямая ссылка на GitHub автоматически начинает обзор: сведения о
публичном проекте, часть README и выбранный каталог. Ссылка на файл открывает
его фрагмент с номерами строк. Ветки, теги и коммиты разрешаются в конкретный
SHA; ответы по исходникам содержат постоянную ссылку на прочитанные строки.
Дельта сохраняет выбранный проект и коммит на сутки отдельно для пользователя
и чата. Поэтому после ссылки можно спросить «А где там реализована память?».
Удаление памяти пользователя очищает также выбранные проекты.

Подключены четыре инструмента: `github_get_repo`, `github_list_tree`,
`github_read_file`, `github_search_files`. Последний ищет имена в выбранной
странице каталога; содержимое нужного файла читается следующим инструментом.
Каталоги выдаются страницами до 40 записей, продолжение задаётся `next_offset`.
Файл ограничен 384 КБ, фрагмент — 80 строками и 8000 символами. В первичном
обзоре фрагменты короче; для продолжения модель может запросить следующие
строки. Частичные результаты явно отмечаются. Обзор не означает чтение всего
репозитория. Ссылки на PR пока обрабатываются обычным чтением страниц и не
означают анализ diff. Для неоднозначных веток со слешами проверяется до четырёх
продолжений имени; сложную ревизию можно указать явно в аргументе `ref`.

Запросы выполняются существующим aiohttp, дополнительная библиотека не нужна.
Используются только GET на фиксированный `api.github.com`, без авторизации,
доступа к аккаунту пользователя, клонирования и исполнения кода. Приватные
репозитории не подключены. Содержимое — недоверенные данные; инструкции из
README или исходников не дают полномочий. Секретные пути, симлинки и подмодули
не раскрываются. Возможные секретные литералы Python скрываются перед выдачей.

HTTP-ответ ограничен 1 MiB и 8 секундами, одновременно идут до трёх запросов.
Кеш на пять минут содержит до 128 ответов; одинаковые запросы объединяются.
Ожидающих операций не больше 12, локальный бюджет — до 50 HTTP-запросов в час.
Ошибки источника показываются как статус чтения без его тела и заголовков.
При ограничении API бот может продолжать обсуждение уже переданных фрагментов,
но не должен придумывать непрочитанные файлы.

Основа реализации: [Git Trees API](https://docs.github.com/en/rest/git/trees),
[ветки](https://docs.github.com/en/rest/branches/branches),
[теги](https://docs.github.com/en/rest/git/tags) и
[лимиты публичного API](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api).
