# Авторство, достоверность и ритм ответов

Приложение передаёт Telegram ID, отображаемое имя, username и отметку пересылки
отдельным JSON-блоком. ID — фактический аккаунт доставки; имя задаёт сам пользователь
и оно не является инструкцией или правом доступа. «[Codex]» внутри текста не меняет
владельца памяти и роль создателя. Автор цитаты и аккаунт, передающий цитату,
могут отличаться: модель получает явное правило различать их.

Обычные новые ходы из Telegram сохраняют ID отправителя в истории SQLite. В запросе
модели он передаётся полем `name`, отдельно от `content`; самостоятельные сообщения
остаются только ролью `assistant`. Старые ходы без ID читаются без выдуманного автора.

Для очередного ответа берутся начала восьми последних незакрытых ответов Дельты,
включая самостоятельные реплики. Модель видит собственные повторения, частоту
вопросов в конце и ремарок. Этот блок ограничен и не меняет сохранённый текст;
короткий стиль не запрещает подробные технические ответы.

Доступ к архиву сообщается для текущего аккаунта и режима. Частные инструменты не
попадают в обзор модели там, где они недоступны. О причинах сбоев и реализации
можно утверждать только то, что подтверждено данными приложения или инструментом;
старые ответы персонажа и догадки пользователя не заменяют проверку.

Шесть показателей настроения имеют объяснённую условную шкалу и рекомендации по
интонации. Низкое число интереса не означает процент любопытства или отказ общаться.
Наводящий вопрос не требует автоматического согласия.

Модульные тесты проверяют сборку и изоляцию контекста на подставных данных. Ручной
`scripts/evaluate_dialogue.py` дополнен случаями наводящих вопросов, неизвестного
провайдера и причин дубля; его запуск с настоящим API расходует лимит и требует
отдельного решения. Подставная модель не доказывает, что реальная модель никогда
не нарушит стилевое правило.
