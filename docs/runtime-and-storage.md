# Лимиты, стадии ответа и хранилища

`LLM_DAILY_REQUEST_LIMIT=300` задаёт общий лимит API-попыток модели на пользователя
в сутки по Москве. Считаются диалог, классификация, извлечение фактов, анализ
изображений/аудио, перевод, части документов, фоновое сообщение и retries.
Резервирование выполняется атомарно в SQLite перед каждой попыткой; сетевой запрос
не держит транзакцию. Неудачные и отменённые попытки также расходуют зарезервированное
место. Число обычных входящих сообщений не используется вместо числа API-попыток.

Счётчики и сообщённые API входные/выходные токены хранятся в `llm_usage.db`, без
текста сообщений, файлов и промптов. Отсутствующее usage отмечается отдельно,
а не выдаётся за нулевой расход. Поздний ответ после полуночи относится к дню
резервирования. Повторная запись usage не удваивает токены. `/reset`, изменение
режима, смена чата и перезапуск не обнуляют счётчик. При исчерпании лимита запросы
к модели отклоняются с понятным сообщением; неплатные команды и возрастная защита
продолжают работать. При недоступности учёта новая попытка API не выполняется.
Собственная статистика доступна по подписанному `GET /api/usage`; чужой ID из
тела или query не используется. Служебные операции без пользователя не относятся
к пользовательской квоте.

`ResponseEngine._respond_for_user` координирует стадии:

1. `_apply_reply_gates`: остановка, локальные ответы и состояние текущего запроса.
2. `_classify_and_load_facts`: реакция и факты.
3. `_collect_reply_context`: состояние, память, сцена, история и промпт.
4. `_call_reply_model`: запрос и обработка ошибок API.
5. `_postprocess_reply`: нормализация и эпизодическая память.

Возрастная проверка, отмена незавершённых ответов, блокировка состояния и запись
истории после доставки остаются на прежних местах. Визуальный контекст выделен
в `visual_reply_context.py`; существующие правила и пользовательские профили
сохранены.

`UsersRepository` использует `users.db`. Первое обращение импортирует прежний
`users.json` в одной транзакции, удаляя дубликаты и сохраняя порядок. Маркер
импорта записывается в той же транзакции; ошибка не оставляет частичный список.
Исходный JSON сохраняется без изменений. После миграции он архивный: удалённые
в SQLite пользователи не возвращаются при перезапуске. Новая установка работает
без JSON. Backup/restore поддерживает новые базы и прежний формат.

Mini App загружает `/static/app.js` из пакета; HTML больше не содержит inline JS.
`script-src` разрешает собственный сервер и Telegram SDK, без `unsafe-inline` и
`unsafe-eval`. `object-src 'none'` и `base-uri 'none'` запрещают плагины и подмену
базового URL. Inline CSS остаётся разрешённым. JS включён в wheel/sdist, ответ
имеет JavaScript MIME, `nosniff` и требует обновления кеша. Проверка CSP в Edge
использует реальные HTTP-заголовки и подтверждает блокировку inline-скрипта и
inline-обработчика; сетевые вызовы Telegram и модели заменены заглушками.
