# Контекст исходящих сообщений

Раньше обычные ответы, инициативы, дополнения, напоминания и автообзоры учитывались
разными маршрутами. У обзора дополнительно исключалась активная RP-сцена: вопрос
«эти изменения тебе помогут?» мог продолжить сцену и получить старый патчноут.

Общий middleware Telegram-клиента сохраняет успешные отправки вне обычного ответа
движка: текст, подписи к вложениям, отметку о стикере или типе вложения. Это включает
инициативы, новости при наличии соответствующего отправителя, обзоры кода,
напоминания, дополнения и сообщения создателя. Обычные ответы уже сохраняет движок.
Содержание картинки, видео или аудио по отметке о вложении не выдумывается.
Редактирование старого сообщения, статус набора и неудачная отправка не становятся
новой репликой. Повтор одного Telegram message_id не создаёт дубль. Ошибка базы
не повторяет доставку и не выводит текст сообщения в журнал приложения.

Журнал outgoing_messages находится в memories.db и разделён по личным чатам.
Хранится до 32 отправок на чат; в запрос попадают до восьми последних новых
отправок за семь суток, каждая до 4096 символов. Общий бюджет истории модели
дополнительно ограничивает передаваемый текст. Это недавний контекст, а не полный
архив. Фоновая очистка не требуется: старые записи данного чата удаляются при
следующей записи. Полное забывание удаляет журнал вместе с разговорной памятью.

Подтверждённые сообщения добавляются в историю assistant перед текущим вопросом.
Вымышленной реплики пользователя нет. Инициативы и дополнения, уже имеющиеся в
истории, повторно не добавляются. Авторство текста создателя отмечается отдельно.
После успешного ответа недостающие отправки и позиция чтения сохраняются вместе
с настоящим ходом диалога. Новые поля JSON истории необязательны при чтении старых
записей; старые настройки и профиль не меняются. Позиция отдельна для каждого чата,
в том числе при разрешённой общей памяти связанных аккаунтов.

Позиция учитывает только отправки, увиденные перед генерацией. Поэтому сообщение,
пришедшее во время ответа, остаётся для следующего хода, даже если оно первое в
журнале. Неудачная доставка ответа не продвигает позицию. Перезапуск сохраняет её.
Явный ответ на другое сообщение или пересылка используют собственный контекст;
более старое фоновое сообщение затем не перехватывает тему.

Вопрос о новом самостоятельном сообщении обсуждается вне RP без сброса её настроек.
Следующее «а подробнее?» продолжает обсуждение. Явное игровое действие или просьба
вернуться в RP возвращает сцену. Свежий отчёт не подменяется журналом установленной
сборки; патчноут доступен по прямому вопросу о нём. Для уже отправленных до обновления
обзоров остаётся прежняя подтверждённая запись доставки.

Регрессионные проверки используют синтетические данные и подменённые Telegram и
модель. Они проверяют реальный порядок SDK-сообщений, доставку через Telegram session
middleware, повторный запуск, ошибки, отмену, несколько отправок, границы чатов и
сохранение обсуждения при активной сцене. Платных оценочных запросов нет.
